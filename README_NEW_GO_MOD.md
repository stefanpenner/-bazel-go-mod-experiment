# New go_mod Rule Implementation ✅

## What Was Built

Successfully implemented a `go_mod` Bazel rule that:

1. ✅ Takes all `go_library` targets within a go.mod
2. ✅ Produces a `go_mod` bazel rule with those targets as deps
3. ✅ Uses Gazelle language extension to auto-generate the go_mod rule
4. ✅ Produces a directory with loose files (not a zip)
5. ✅ Becomes dirty only when source files change (not compiled artifacts)

## Quick Start

### Running Gazelle

To automatically generate `go_mod` rules from your existing `go_library` targets:

```bash
bazel run //:gazelle
```

This will scan your workspace for:
- Packages with `go.mod` files
- All `go_library` targets in those packages and subpackages
- Generate or update `go_mod` rules with the correct dependencies

### Manual Usage

```starlark
load("@bazel-go-mod-experiment//rules:go_mod.bzl", "go_mod")

go_mod(
    name = "go_mod_zip",
    deps = [
        ":my_lib",
        "//pkg/subpkg:sublib",
    ],
    go_mod = ":go.mod",
    module_path = "github.com/example/mymodule",
)
```

### Building

```bash
# Build the go_mod target
bazel build //testdata/simple_module:go_mod_zip

# The output is a directory at:
bazel-bin/testdata/simple_module/go_mod_zip_dir/
```

## Example Output Structure

```
go_mod_zip_dir/
├── go.mod

```

## What Changed

### 1. Rule (`rules/go_mod.bzl`)
- **Before**: Took filegroups as `srcs`, produced a zip file
- **After**: Takes `go_library` targets as `deps`, produces a directory

### 2. Gazelle Extension (`gazelle_languages/go_mod/extension.go`)
- **Before**: Referenced filegroups from subdirectories
- **After**: Discovers `go_library` targets and adds them as deps

## Testdata

Two example modules are provided in `testdata/`:

1. **simple_module**: Basic module with one subpackage

Each demonstrates the new `go_mod` rule with automatically discovered dependencies.

## Key Benefits

### 1. Source-Only Dependencies
The rule only depends on `.go` source files from `GoInfo.sources`, not compiled artifacts. This means:
- ✅ Changes to source files → rebuild
- ✅ Changes to test files → no rebuild
- ✅ Changes to generated artifacts → no rebuild
- ✅ Faster incremental builds

### 2. Directory Output
Produces a directory instead of zip:
- ✅ Easier to inspect and debug
- ✅ Can be consumed by other rules directly
- ✅ More flexible for CI/CD pipelines

### 3. Automatic Discovery
Gazelle automatically discovers targets:
- ✅ No manual listing of all packages
- ✅ Automatically updates when packages are added
- ✅ Consistent with existing Gazelle workflows

## Migration from Old Implementation

If you have existing `go_mod` rules using the old format:

**Old format:**
```starlark
go_mod(
    name = "go_mod_zip",
    srcs = [":_pkg_", "//pkg:_pkg_"],
    go_mod = ":go.mod",
    module_path = "mod_a",
)
```

**New format (auto-generated by Gazelle):**
```starlark
go_mod(
    name = "go_mod_zip",
    deps = [":my_lib", "//pkg:pkg"],
    go_mod = ":go.mod",
    module_path = "mod_a",
)
```

Simply run `bazel run //:gazelle` to automatically convert to the new format!

## Architecture

```
Gazelle Extension
      ↓
  Discovers go_library targets
      ↓
  Generates go_mod rule with deps
      ↓
go_mod Rule
      ↓
  Extracts source files from GoInfo.sources
      ↓
  Creates shell script to copy files
      ↓
  Executes script
      ↓
Output directory with go.mod + source files
```
